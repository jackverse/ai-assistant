# 11 — 里程碑与验收

## 0. 总体分期

用户明确：**清理先不做，先做扫描。** 因此 M1–M6 全部是只读（扫描 + 分析 + 生成计划），M7 才引入写操作。

```
M0 脚手架 ──► M1 扫描骨架 ──► M2 软件清单 ──► M3 路径发现 ──► M4 可清理性判定 ──► M5 报告 ──► M6 迁移计划 ──► M7 执行器（后续）
   环境        盘符+遍历+大小     注册表+规则库     环境变量+KnownFolder   四级模型+规则库      table/html      只出计划不执行     真正删/搬
                只读 ────────────────────────────────────────────────────────────────────────┘        写操作 ─┘
```

**每个里程碑都必须能在本机真实数据上验证**（验收基准见 `12-实测基线与样例数据.md`）。

## 推荐实施顺序的理由

1. **M1 先做，且做扎实**：扫描是所有分析的输入，且 reparse/长路径/编码这三类坑如果留在后面，会污染所有下游逻辑，返工成本极高。
2. **M2/M3 可以并行**：软件清单（注册表）与路径发现（文件系统 + 环境变量）依赖面重叠很小。
3. **M4 在 M5 之前**：先有正确的判定，再想怎么展示。反过来会为了好看的报告而扭曲判定逻辑。
4. **M5 的 table 版尽早出**：自己每天用它看本机数据，是发现规则缺陷最快的途径。
5. **M6 只出计划不执行**：这一步的产出（`plan.json`）本身就是给用户审阅的，正好卡在用户要求的「清理先不做」边界上，而且能让人工复核计划质量，为 M7 降低风险。
6. **M7 单独且最后**：写操作的风险与只读差一个量级，必须在规则经过真实数据充分验证之后。

## 本期（M0–M6）完成时的交付标准

```
✅ 单个 winclean.exe，零运行时依赖，可直接双击/命令行运行
✅ winclean scan --disk C   30 秒内完成，零写操作，无需管理员权限
✅ 报告首屏给出「预计可回收 ≈ 100 GB」的三分类总览
✅ 准确归因 C 盘 233 GB 的 Top 10 占用项
✅ 零误报：不把任何用户数据标为可安全清理
✅ 生成 ≥ 50 GB 的可迁移计划，每条含机制、风险、预检结果、注意事项
✅ 系统设置建议含取舍选项（页面文件保留小分页文件 / hiberfil 三个选项）
✅ 诚实报告 84% 归因覆盖率与 16 GB 缺口
✅ 全程中文正确（飞书/零信浏览器/微信开发者工具/图片 等）
✅ 完整设计文档 + 规则库 + 测试套件
```

**还没做的（明确告知用户）**：
- ❌ 实际执行清理
- ❌ 实际执行迁移
- ❌ 实际修改系统设置
- ❌ 重复文件查找
- ❌ GUI

这三项 ❌ 的能力在 M7 实现前，用户需要按 `plan.json` 的指示手工操作——而计划本身已经给出了每步的确切命令，所以「手工执行」也是可行的，只是没有自动化与回滚保护。
