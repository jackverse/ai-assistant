# 10 — 规则库规范

规则库是本工具的**知识层**：把「哪个软件是什么、有哪些路径、哪些能删、怎么迁」从代码里剥离出来，用 YAML 表达并 `embed` 进二进制。

**为什么必须外置**：知识增长的速度远快于代码。本机实测就发现规则库需要覆盖 `docker_data.vhdx`、`Yarn\Cache`、`~/.cache/puppeteer`、`@mmx-agentelectron-updater` 这些**代码作者凭直觉写不出来**的东西。硬编码在 Go 里意味着每加一个软件就要改代码、重新编译、走一遍发版流程——这不可持续。

## 1. 目录组织

```
internal/catalog/data/
├── system/
│   ├── protected.yaml          # L0 硬阻断（系统关键、凭据、用户内容）
│   ├── baseline.yaml           # 系统路径基线（Temp/日志/转储/回收站…）
│   ├── system-tweaks.yaml      # 页面文件、休眠等系统设置项
│   └── knownfolders.yaml       # 已知文件夹的迁移策略
├── patterns/
│   ├── cache-names.yaml        # 命名模式 → PathKind/置信度（Cache/GPUCache/Code Cache…）
│   ├── updater-residue.yaml    # *-updater / * Installer 等更新包残留
│   └── vhd.yaml                # 虚拟磁盘探测（*.vhdx/*.vhd）
└── apps/
    ├── browsers.yaml           # Chrome/Edge/零信浏览器/Brave/Firefox
    ├── devtools.yaml           # VS Code/Cursor/JetBrains/DBeaver/Postman/Termius
    ├── ai-tools.yaml           # Claude Code/ZCode/MiniMax Code/Trae/opencode
    ├── runtimes.yaml           # nvm/Node/Python/JDK/.NET/Go/Android SDK
    ├── package-managers.yaml   # npm/yarn/pnpm/pip/maven/gradle/cargo/nuget
    ├── im.yaml                 # 微信/QQ/飞书/钉钉/Discord
    ├── containers.yaml         # Docker Desktop/WSL2/Podman
    ├── office.yaml             # WPS/Office/Xmind/Adobe
    ├── game-platforms.yaml     # Steam/Epic/Battle.net
    └── misc.yaml               # SwitchHosts/Clash Verge/ToDesk/Quark…
```

**加载顺序**：`system` → `patterns` → `apps`。同 ID 的规则后加载者**覆盖**前者（便于用户自定义规则覆盖内置规则，但 L0 不可被覆盖，见 §6）。

## 2. App 规则 schema

```yaml
# 一个 AppRule 描述一个软件
id: google.chrome                      # 必填，全局唯一，点分层级
display_name: Google Chrome            # 必填，规范显示名
aliases:                               # 可选，用于匹配注册表 DisplayName
  - Chrome
  - Google Chrome
  - chrome.exe
publisher: Google LLC                  # 可选，用于匹配与歧义消除
publisher_aliases: [Google, Google Inc, Google LLC]
category: browser                      # 必填，有限枚举（见 04 §4.1）
purpose: "网页浏览器，用于访问互联网站点"   # 必填，一句话中文用途
homepage: https://www.google.com/chrome/

# 匹配规则（决定这个 AppRule 是否适用于某个注册表条目）
match:
  display_name_regex: "(?i)^google chrome"     # 可选
  publisher_regex: "(?i)^google"               # 可选
  install_path_contains: ["\\Google\\Chrome"]  # 可选
  exe_names: ["chrome.exe"]                    # 可选，用于便携版识别
  priority: 10                                 # 数字大者优先（解决多规则都匹配的情况）

# 关键：这个软件在磁盘上的目录构成
paths:
  - kind: data                                 # install/cache/data/config/download/log/temp/dump/runtime/vhd
    template: "%LOCALAPPDATA%\\Google\\Chrome\\User Data"
    level: L0                                  # 可清理性等级
    subtype: credential                        # L0/L1 的子类
    note: "浏览器用户数据（配置、书签、Cookie、历史）"
    reason: "包含书签、保存的密码、登录状态。删除会导致密码与书签永久丢失"
    consequence: "书签、密码、登录态全部丢失"
    recommendation: "整体迁移到 D 盘（Junction），而非删除"
    # 重要：声明其下哪些子路径例外（覆盖父级等级）
    children:
      - name: "Default\\Cache"
        kind: cache
        level: L2
        reason: "网页缓存，可重建"
        consequence: "下次访问网站变慢，需重新下载资源"
      - name: "Default\\Code Cache"
        kind: cache
        level: L2
        reason: "JavaScript 编译缓存，可重建"
      - name: "Default\\GPUCache"
        kind: cache
        level: L2
      - name: "Default\\Cache\\Cache_Data"     # ← 现代 Chrome 把缓存移到这里
        kind: cache
        level: L2
        reason: "网页缓存（Chrome 100+ 的新布局）"
      - name: "Default\\Service Worker\\CacheStorage"
        kind: cache
        level: L2
      - name: "Default\\Service Worker\\ScriptCache"
        kind: cache
        level: L1
        reason: "Service Worker 脚本缓存，删除会导致离线应用需重新注册"
      - name: "Default\\Login Data"
        level: L0
        subtype: credential
        reason: "保存的网站密码"
      - name: "Default\\Bookmarks"
        level: L0
        subtype: user-generated
        reason: "书签"
      - name: "Default\\History"
        level: L0
        subtype: user-generated
      - name: "Default\\Web Data"
        level: L0
        subtype: credential
        reason: "自动填充数据（含支付信息）"
      - name: "Local State"
        level: L0
        subtype: credential
        reason: "含加密密钥引用，丢失会导致密码无法解密"
    # Profile 通配（多 profile 的软件）
    glob_profile:
      pattern: "^(Default|Profile \\d+|System Profile|Guest Profile)$"
      index_file: "Local State"                # 优先从这里读 profile 列表
      index_json_path: "profile.info_cache"

  - kind: data
    template: "%LOCALAPPDATA%\\Google\\Chrome\\User Data\\{Profile}\\Cache"
    # ↑ 简写形式，等价于上面的 children 声明（两种写法都支持，后者更简洁）

# 迁移声明
migration:
  supported: true
  # 按优先级列出可用机制，引擎选第一个可行的
  mechanisms:
    - type: junction
      reason: "Chrome 无官方迁移设置，Junction 对浏览器透明且可回滚"
      risk: low
    - type: app-config
      flag: "--user-data-dir"
      reason: "官方支持但需改快捷方式参数，易被升级覆盖"
      risk: medium
  # 额外注意事项
  caveats:
    - "迁移前必须完全退出 Chrome（含后台进程）"
    - "迁移后首次启动会重建部分缓存，属正常"

# 附加动作（针对这个软件的推荐操作）
actions:
  - type: run-command
    command: "chrome"
    args: ["--clear-cache"]
    note: "也可用 Chrome 内置的清理功能"
```

### 2.1 字段说明

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | ✅ | 全局唯一，点分。约定：`<vendor>.<product>` |
| `display_name` | ✅ | 用户可见名 |
| `aliases` | | 匹配注册表 DisplayName（大小写不敏感的子串或全等） |
| `category` | ✅ | 有限枚举，会被判定与报告分组引用 |
| `purpose` | ✅ | 一句话中文用途，**回答"这软件是干嘛的"** |
| `match.*` | | 匹配条件，详见 §2.2 |
| `paths[]` | ✅ | 目录构成，是规则库的核心价值 |
| `paths[].children[]` | | 子路径等级覆盖（**精细度的关键**） |
| `paths[].glob_profile` | | 多 profile 展开 |
| `migration` | | 迁移声明；缺失表示"不建议迁移" |
| `actions` | | 附加推荐动作 |

### 2.2 匹配与优先级

```
匹配顺序（第一个成功的即采用，但还要看 priority）：
  1. match.display_name_regex    对注册表 DisplayName
  2. match.publisher_regex       对 Publisher
  3. match.install_path_contains 对反推出的 InstallLocation
  4. aliases 精确匹配（归一化后）
  5. aliases 子串匹配（归一化后）

歧义处理：
  · 多个规则都匹配 → 取 priority 最大者
  · priority 相同 → 取 aliases 匹配更精确者（精确 > 子串）
  · 仍相同 → 记录 warning，取 id 字典序最小者（保证确定性）

归一化函数（用于 aliases 与 DisplayName 比较）：
  1. Unicode NFKC 归一化（处理全角/半角）
  2. 去除版本号模式：\(.*?\)、\d+(\.\d+)+、v\d+、x64、x86、64-bit、32-bit
  3. 去除 "(User)"、"(current user)"、"(machine)" 等安装范围后缀
  4. 去除前导/尾随空白与多余空格
  5. ASCII 部分转小写（中文保持原样）
```

**实测验证点**（来自 `12`）：
- `WPS Office (12.1.0.28505)` → 归一化 → `wps office`
- `DBeaver 22.3.2 (current user)` → 归一化 → `dbeaver`
- `Microsoft Visual Studio Code (User)` → 归一化 → `microsoft visual studio code`
- `Postman x64 11.87.4` → 归一化 → `postman`
- `Python 3.14.6` → 归一化 → `python`
- `飞书` → 不变（中文），需 `aliases: [飞书, Feishu, Lark, LarkShell]`

## 3. Path 规则（系统基线）

```yaml
# system/baseline.yaml
- id: baseline.temp-user
  template: "%LOCALAPPDATA%\\Temp"
  kind: temp
  level: L2
  reason: "用户临时文件，程序退出后通常不再需要"
  consequence: "无功能损失；正在使用的临时文件会被跳过"
  min_age_hours: 24                # 关键：必须 > 24h 才可操作

- id: baseline.wu-download

  kind: cache
  level: L1                        # 需停服务，故为 L1
  precondition:                    # 前置条件
    - type: stop-service

  reason: "Windows 更新下载缓存（本机实测 544 MB）"
  consequence: "已下载未安装的更新需要重新下载"

  reason: "组件安装日志"
```

## 4. 命名模式规则（启发式）

```yaml
# patterns/cache-names.yaml
- id: pattern.cache.dirname
  match_dirname: ["Cache", "Caches", "cache", "cache_data", "Cache_Data"]
  kind: cache
  confidence: 0.90
  level_ceiling: L2                 # 置信度够高时可判 L2

- id: pattern.cache.code
  match_dirname: ["Code Cache", "CodeCache", "code_cache"]
  kind: cache
  confidence: 0.95
  level_ceiling: L2
  note: "Chromium 系特有的 JS 编译缓存，必然是缓存"

- id: pattern.cache.gpu
  match_dirname: ["GPUCache", "ShaderCache", "GrShaderCache", "GpuCache"]
  kind: cache
  confidence: 0.95
  level_ceiling: L2

- id: pattern.cache.serviceworker
  match_dirname: ["CacheStorage"]
  kind: cache
  confidence: 0.90
  level_ceiling: L2

- id: pattern.data.serviceworker
  match_dirname: ["Service Worker"]
  kind: cache
  confidence: 0.65                 # 含 CacheStorage(缓存) 与注册信息(非缓存)
  level_ceiling: L1                # ← 置信度不足，上限降为 L1
  note: "既含缓存也含 Service Worker 注册信息，需谨慎"

- id: pattern.data.indexeddb
  match_dirname: ["IndexedDB"]
  kind: data
  confidence: 0.50
  level_ceiling: L1
  note: "网页离线数据，删除可能丢失本地保存的内容"

- id: pattern.data.storage
  match_dirname: ["Local Storage", "Session Storage", "blob_storage", "File System"]
  kind: data
  confidence: 0.40
  level_ceiling: L1
  note: "网页本地存储，删除会丢失登录态"

- id: pattern.dump.crashpad
  match_dirname: ["Crashpad", "Crash Reports", "CrashDumps"]
  kind: dump
  confidence: 0.90
  level_ceiling: L2

- id: pattern.log.dirname
  match_dirname: ["logs", "log", "Logs", "Log"]
  kind: log
  confidence: 0.85
  level_ceiling: L1                # 日志可能有诊断价值

# patterns/updater-residue.yaml  ← 本机实测 1.8 GB 的一类
- id: pattern.updater.suffix
  match_dirname_regex: "(?i)[-_ ]?updater$|^@.*updater$"
  kind: cache
  confidence: 0.85
  level_ceiling: L2
  reason: "应用自动更新残留目录（本机如 @mmx-agentelectron-updater）"
  consequence: "无功能损失；下次更新会重新下载"
  examples: ["@mmx-agentelectron-updater", "termius-updater"]

- id: pattern.installer.suffix
  match_dirname_regex: "(?i)^.*(installer|setup)[-_ ]?\\d*$"
  kind: cache
  confidence: 0.80
  level_ceiling: L1                # 可能是安装器本体，谨慎
  note: "可能是安装包残留，也可能是正在用的安装器"

- id: pattern.package.installer-file
  match_filename_regex: "(?i)^.*(setup|installer|install)[-_ ]?v?\\d+(\\.\\d+)*\\.(exe|msi)$"
  kind: cache
  confidence: 0.75
  level_ceiling: L1
  min_age_days: 30
  note: "下载的安装包，通常已安装完毕可删；但需 30 天以上更稳妥"

# patterns/vhd.yaml
- id: pattern.vhd.file
  match_filename_regex: "(?i)\\.(vhdx|vhd)$"
  kind: vhd
  level: L3                        # ★ 一律 L3，绝不可删
  confidence: 1.0
  reason: "虚拟磁盘文件，包含虚拟机/容器的全部数据"
  consequence: "删除将导致虚拟机/容器/镜像数据全部丢失"
  recommendation: "迁移到其他盘，或压缩以回收内部空洞"
  ownership_hint:                  # 归属推断
    - path_contains: "\\Docker\\wsl\\disk\\" → owner: "Docker Desktop"
    - path_contains: "\\Packages\\"          → owner: "WSL2 发行版"
    - path_contains: "\\Hyper-V\\"           → owner: "Hyper-V 虚拟机"
```

### 4.1 置信度与等级上限的关系

**关键设计**：模式规则声明的是 `level_ceiling`（上限），不是最终等级。实际等级取 min(上限, 由置信度推出的等级)。

```
置信度 ≥ 0.90 且父目录是已知软件的数据目录  →  可用 level_ceiling（最高 L2）
置信度 ≥ 0.70                              →  最高 L1
置信度 <  0.70                              →  最高 L3
最终 = min(level_ceiling, 置信度推出的上限)
```

**为什么设上限而不是直接定级**：因为命名模式是**启发式的**，一个叫 `Cache` 的目录理论上可以是用户自己建的、装着重要数据的目录。`level_ceiling` 让规则作者显式表达「这个模式最多能信到什么程度」，而置信度门控让引擎进一步收紧。

## 5. 系统设置规则

```yaml
# system/system-tweaks.yaml
- id: tweak.pagefile
  title: "将虚拟内存移到其他盘"
  target_file: "pagefile.sys"
  current_size_from: "volume_root"     # 从卷根读取实际大小
  max_reclaimable_ratio: 0.95          # 可回收当前大小的 95%（C 盘保留最小分页文件）
  need_admin: true
  need_restart: true
  reversible: true
  revert_hint: "在「系统属性 → 高级 → 性能 → 虚拟内存」中改回 C 盘"
  options:
    - label: "完全移到 D 盘（C 盘保留 2 GB 用于崩溃转储）"
      command: "wmic pagefileset where name='C:\\\\pagefile.sys' set InitialSize=2048,MaximumSize=2048"
      recommended: true
      effect: "无功能影响；C 盘保留 2 GB 以保证蓝屏时能生成转储"
    - label: "完全移到 D 盘（C 盘不留）"
      effect: "⚠️ 系统将无法生成崩溃转储，蓝屏问题难以诊断"
    - label: "不动"
  reason: "虚拟内存文件（本机实测 24.3 GB）。可移到 D 盘释放 C 盘空间"
  effects:
    - "需要重启才能生效"
    - "若 D 盘是机械盘或外置盘，可能影响系统性能（本机 D 盘为 931 GB 内置盘，无影响）"
  precheck:
    - type: volume_has_space
      volume_from: target
      need_bytes: "{current_size} * 0.95"
    - type: target_volume_type
      allow: [fixed]

- id: tweak.hiberfil
  title: "关闭休眠以释放休眠映像文件"
  target_file: "hiberfil.sys"
  current_size_from: "volume_root"
  need_admin: true
  need_restart: false
  reversible: true
  revert_hint: "powercfg /h on"
  options:
    - label: "完全关闭休眠"
      command: "powercfg /h off"
      reclaimable_ratio: 1.0
      effect: "失去休眠能力，同时失去「快速启动」（开机可能变慢）"
      recommended: false
    - label: "缩小休眠文件到内存的 40%"
      command: "powercfg /h /size 40"
      reclaimable_ratio: 0.6
      effect: "保留「快速启动」，但失去完整休眠能力。本机预计回收约 4 GB"
      recommended: true       # ← 更好的取舍
    - label: "完全关闭并保留快速启动（powercfg /h /type reduced）"
      command: "powercfg /h /type reduced"
      reclaimable_ratio: 0.5
      effect: "保留快速启动，失去休眠"
  reason: "休眠映像文件（本机实测 9.7 GB，约为内存的 40%）"
  note: "本文件不能直接删除，必须通过 powercfg 关闭功能"
```

## 6. 优先级与覆盖规则

```
加载顺序：
  1. 内置 system/     （protected → baseline → tweaks → knownfolders）
  2. 内置 patterns/
  3. 内置 apps/
  4. 用户规则目录（%APPDATA%\winclean\rules\*.yaml）

覆盖规则：
  · 同 id 的规则，后加载者覆盖先加载者
  · 但：protected.yaml 中的 L0 规则**不可被覆盖**（加载后进入独立的硬阻断集合，
    与规则库解耦，见 06 §3.1）
  · 用户规则可新增规则、可覆盖内置的 apps/ 规则
  · 用户规则可把某条内置规则的 enabled 设为 false 来禁用（但 L0 不可禁用）

冲突检测（rules validate 命令）：
  · 两个 AppRule 的 id 重复 → 错误
  · 两个 AppRule 的 match 条件相同但 category 不同 → 警告
  · 一个路径同时被 L0 与 L2 规则匹配 → 错误（L0 优先，但要报错提醒作者）
  · level_ceiling 与 level 矛盾（如 level: L2 但 confidence 0.5）→ 错误
  · template 展开后不是绝对路径 → 错误
  · 引用了不存在的变量 → 错误
```

### 8.2 规则测试 fixture

每条规则可以附带测试用例：

```yaml
- id: google.chrome
  # ...
  tests:
    - name: "Chrome Cache 应为 L2"
      path: "%LOCALAPPDATA%\\Google\\Chrome\\User Data\\Default\\Cache"
      expect_level: L2
      expect_kind: cache
    - name: "Login Data 应为 L0"
      path: "%LOCALAPPDATA%\\Google\\Chrome\\User Data\\Default\\Login Data"
      expect_level: L0

    - name: "多 profile 展开"

      expect_level: L2
      expect_matched: true
```

`winclean rules test` 会跑全部 fixture，任何失败即报错。

## 9. 用户自定义规则

### 9.1 用法

```
%APPDATA%\winclean\rules\
├── my-apps.yaml            # 用户自己的软件规则
└── disable.yaml            # 禁用某些内置规则
```

```yaml
# disable.yaml
disable:
  - "baseline.prefetch"       # 我不想看到 Prefetch 的建议
  - "npm.cache"               # 我自己管理 npm 缓存
# 注意：L0 规则不可禁用，写了会被忽略并警告
```

### 9.2 生成规则骨架（降低贡献门槛）

```bash
$ winclean rules suggest --path "%APPDATA%\secoresdk"
分析目录：%APPDATA%\secoresdk  (857 MB)
  文件构成：
    *.dll   42 个 (312 MB)     ← 疑似原生库
    *.dat   8 个  (298 MB)     ← 数据文件
    *.log   3 个  (247 MB)     ← 日志
    *.json  12 个 (0.4 MB)
  存在可执行文件：secoresdk.exe, secoreshield.exe
  推断：疑似安全软件 SDK（secoreshield 命名）
```

生成的规则骨架（写到 stdout，由用户确认后另存）：

```yaml
- id: secoresdk
  display_name: "Scoresdk"
  category: unknown            # ← 请人工确认
  purpose: "待补充"
  paths:
    - kind: unknown
      template: "%APPDATA%\\secoresdk"
      level: L3                # ← 未确认前一律 L3
      reason: "未识别，需人工确认用途"
```

请补充 `purpose` 与 `category` 后保存到 `%APPDATA%\winclean\rules\my-apps.yaml`

**关键**：自动生成的骨架**默认 L3**，绝不因为"看起来像缓存"就给 L2。人工确认是必须的。

## 10. 版本与兼容

| 字段 | 说明 |
| --- | --- |
| 每条规则有隐含的 `rules_version`（文件级声明） | 规则库整体版本 |
| `scan.json` 记录 `catalog_version` | 报告可追溯用了哪版规则 |
| 规则变更影响等级时 | 通过 `TestLevelRegression` 检出并需人工 review |
| 规则库向后兼容 | 新增字段可选；删除字段需升 major |

```yaml
# 每个文件头部可选声明
__meta__:
  version: "1.2.0"
  last_updated: "2026-09-14"
  maintainer: "zcode"
```
