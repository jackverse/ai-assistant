# 19 — 决策式清理界面：不给数据，给结论

> 用户反馈：元素太多、很乱、看不出来该怎么选择、哪些删除哪些不删除。

---

## 1. 问题诊断

当前扫描页展示的是**文件系统的事实**（路径、字节、文件数、深度）。
这对开发者有意义，但对普通用户来说就是一堵数据墙。

**根因：我们把「分析」的责任丢给了用户。**
扫描出了 100 个目录，然后让用户自己判断哪个能删哪个不能——
那用户要这个工具干什么？

## 2. 设计：三个色区 + 一键操作

```
✅ 可以删除（不影响任何功能）                    小计 1.6 GB
────────────────────────────────────────────────
  ☑ 用户临时文件              280 MB
     超过 30 天未使用，删除后无影响
  ☑ npm 缓存                 304 MB
     删除后下次安装时自动重新下载
  ☑ pip 缓存                 305 MB
     删除后下次安装时自动重新下载
────────────────────────────────────────────────
  [删除已勾选 · 释放 891 MB]

⚠️ 需要你决定（有代价但可恢复）                  小计 66 GB
────────────────────────────────────────────────
  ☐ Yarn 包缓存               8.2 GB
     删除要重新下载（约 30 分钟），建议迁移而非删除
     → 迁移方法：设 YARN_CACHE_FOLDER 到 D 盘
  ☐ Maven 本地仓库            3.0 GB
     删除要重新下载全部依赖，建议迁移
     → 迁移方法：改 settings.xml 的 localRepository
  ☐ Docker 数据盘            36.0 GB
     删除等于删掉所有镜像和容器！建议迁移
     → 迁移方法：Docker 设置里改 Disk image location
────────────────────────────────────────────────
  [迁移已勾选到 D 盘 · 释放 66 GB]

🚫 不要动（系统和重要数据）                      仅展示
────────────────────────────────────────────────
  Windows 系统                               22.3 GB
  Office                                     4.9 GB
  微信聊天记录                                6.9 GB
  （这些不需要你操作，展示只是让你知道空间去哪了）
```

**三条铁律**：
1. **绿色区默认全选**——用户直接点删除按钮就安全
2. **黄色区默认不选**——需要用户逐个理解后再勾
3. **红色区没有勾选框**——防止误操作

## 3. 实现方式

不需要新的扫描引擎。就是**把已有的扫描结果 + 分类引擎 + 规则库的输出，
从「文件事实」翻译成「三个色区的决策清单」**。

```
已有的：ScanResult + BuildSpaceReport + 规则库
     ↓
新增的：DecisionList 翻译器
     ↓
输出的：[]DecisionGroup（三组，每项含建议与默认勾选状态）
     ↓
前端：纯 checkbox 列表 + 底部操作按钮
```
