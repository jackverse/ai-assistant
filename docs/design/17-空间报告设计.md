# 17 — 空间报告：按人的理解呈现扫描结果

> 需求原话：扫描出来的东西不要太细，我也看不懂。告诉我哪些是系统的、
> 哪些是安装的文件、最后一次使用时间、用的是否频繁、默认数据或缓存
> 路径配置在哪里、是否可以改位置。移动位置根据是否有 AI 来推荐——
> 没有 AI 就人为移动，有 AI 就规划移动路径（工具在一起、软件在一起、
> 代码在一起、工作记录在一起）。

---

## 1. 核心转变：从「文件事实」到「人的理解」

现在的扫描页展示的是**文件系统的事实**：路径、字节、文件数、深度。
这些是给程序看的。用户需要的是**理解**：

| 用户问的 | 我们回答的（现状） | 应该回答的 |
| --- | --- | --- |
| 哪些是系统的？ | `C:\Windows 31.7GB 深度25 181722文件` | 「Windows 系统 · 22.3 GB · 不要动」 |
| 哪些是安装的？ | `C:\Program Files\Microsoft Office\root 4.9GB` | 「Microsoft Office · 上次使用：昨天 · 4.9 GB」 |
| 什么时候用的？ | （没有） | 「上次使用：3 天前」 |
| 用得频繁吗？ | （没有） | 「常用（30 天内用过 12 次）」 |
| 缓存配置在哪？ | （没有） | 「缓存路径：`D:\workplace\...`，可在设置里改」 |
| 能不能搬？ | （在另一页） | 「可以搬到 D 盘 · 方法：改环境变量」 |

**本质：加一层「理解引擎」，把文件事实翻译成人能读懂并直接做决定的语言。**

**三条设计原则**：
1. **按「你能做什么」分组，而不是按「文件在哪」**——用户关心的是"我能删什么/该搬什么"，不是目录树
2. **每个条目回答四个问题**：是什么、多大、多久没用了、能怎么处理
3. **操作按钮按分组放**：整个「可迁移」组一个迁移按钮，整个「可清理」组一个清理按钮——不是每行一个

## 3. 分类引擎

### 3.1 六个分类

| 分类 | 判定依据 | 用户能做什么 |
| --- | --- | --- |
| **系统组件** | 路径在 `C:\Windows`、`Program Files`、页面文件等 | 什么都不用做（部分可改设置如页面文件位置） |
| **已安装软件** | 注册表有记录 + 安装目录匹配 | 看大小决定要不要卸载重装到别的盘 |
| **开发工具与缓存** | 路径含 npm/yarn/pip/maven/.cache/nvm/docker + 规则库 | **迁移到 D 盘**（改环境变量或配置文件）或删除（下次自动重建） |
| **用户数据** | Known Folder 内 + 路径含 Tencent/Cursor/Documents | **不要删**；部分可用软件自带功能迁位置 |
| **可安全清理** | 规则库 L2 级别（临时文件、缓存、更新残留） | **删除**，无功能损失 |
| **没认出来的** | 不匹配任何规则 | 需要用户人工判断；可提交规则建议 |

### 3.2 分类优先级（一个路径只能属于一个组）

```
1. 路径在 Known Folder（Documents/Desktop/Pictures）→ 用户数据
2. 路径在系统区域（C:\Windows、Program Files、pagefile 等）→ 系统组件
3. 路径含 Tencent/WeChat/DingTalk 等 IM 数据 → 用户数据
4. 规则库判定为 L2（可安全清理）→ 可安全清理
5. 路径含包管理器/运行时/构建缓存 → 开发工具与缓存
6. 注册表有安装记录且路径匹配 → 已安装软件
7. 以上都不匹配 → 没认出来的
```

### 3.3 使用频率推断

从目录内文件的 mtime 分布推断：

| 信号 | 判定 | 展示 |
| --- | --- | --- |
| NewestMtime < 3 天 | 最近在用 | 「上次使用：今天/昨天」 |
| NewestMtime < 14 天 | 近期用过 | 「上次使用：N 天前」 |
| NewestMtime < 60 天 | 一两个月没动了 | 「上次使用：N 天前」 |
| NewestMtime ≥ 60 天 | 长期未用 | 「超过 N 天未使用」 |
| 目录内 mtime 分散（min 与 max 差 > 90 天）| 历史悠久 | 追加「历史较久」 |

**这是近似值不是精确值**——mtime 只反映最后写入，不反映读取。但足够回答用户的实际问题：「这个东西我还在用吗？」

## 4. AI 增强层（有 AI 更聪明，没 AI 也能用）

### 4.1 无 AI 时（内置规则兜底）

- 分类靠路径模式 + 规则库（已覆盖本机 Top 30 占用项）
- 使用频率靠 mtime 统计
- 迁移建议靠规则库预设（`Yarn\Cache → 改 YARN_CACHE_FOLDER`）
- 输出：准确的分类与大小，但理由是模板化的

### 4.2 有 AI 时

AI 额外提供三样内置规则做不到的东西：

1. **未知路径的语义理解**——`secoresdk` 规则库不认识，但 AI 可能从名字和上下文推断「疑似安全软件组件」
2. **迁移路径规划**——不只说"这个能搬"，而是给出整体规划：「你是开发者，建议 D 盘按 dev/tools（工具）、dev/cache（缓存）、dev/repos（代码）、work/docs（工作记录）分区」
3. **更自然的解释**——「这个 8.2 GB 的 Yarn 缓存删除后下次安装依赖需要重新下载约 30 分钟，但不会丢失任何项目代码」比「可安全清理（L2 级别）」好懂得多

### 4.3 AI 是否启用要提前告知

```
✨ AI 分析：已启用（qwen38 @ 内网网关）
   AI 能帮你：识别未知目录、给出迁移目录规划、用自然语言解释建议

或者：
📊 AI 分析：未启用
   以下建议基于内置规则，分类和大小是准确的，但无法识别未知目录用途
   或规划迁移路径。到设置里配置大模型可获得更智能的分析。
```

这样用户知道当前建议的「置信来源」，以及开启 AI 能额外得到什么。

- ✅ 分类引擎（6 组，按优先级判定）
