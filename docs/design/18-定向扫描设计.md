# 18 — 定向扫描：按已知模式查找，不扫全盘

> 需求：不要每个文件都扫描，按经验先找大的/已知的（比如 QQ 在哪），
> 找到文件夹就止住。后续操作时再对那一个文件夹做深度扫描。

---

## 1. 两种扫描策略对比

| | 全盘扫描（现有） | 定向扫描（新增） |
| --- | --- | --- |
| 触发 | 用户点「扫描 C 盘」 | 用户问「QQ 占了多少」或「帮我找大文件」 |
| 范围 | C:\ 全部 1.4M 文件 | 只扫已知模式匹配到的路径 |
| 耗时 | 45 秒 | **3–5 秒** |
| 结果 | 完整但大部分不需要 | 精准且够用 |

**两种共存，不替代**：定向扫描是日常入口（快、够用），全盘扫描是深度工具（完整但慢）。

---

## 2. 定向扫描的三步

### 步骤 1：发现目标路径（不碰文件系统，毫秒级）

| 来源 | 发现什么 | 例子 |
| --- | --- | --- |
| 注册表 Uninstall 键 | 已安装软件的 InstallLocation | `D:\workplace\jdk17` |
| Known Folder + 规则库 | 缓存/数据路径 | `%LOCALAPPDATA%\npm-cache` |
| 环境变量 | 工具链路径 | `JAVA_HOME=D:\workplace\jdk17` |
| 常见模式 | 开发缓存/运行时 | `%USERPROFILE%\.cache\*`, `%APPDATA%\npm-cache` |

### 步骤 2：定向测量（每个路径独立，秒级）

对每个发现的路径，用现有扫描引擎跑一次 **bounded scan**：

```go
scan.Run(ctx, scan.Options{
    Roots:    []string{targetPath},
    MaxDepth: 2,        // 只要顶层聚合，不深入
    MinSize:  0,        // 不过滤
    TopFiles: 5,        // 顺带看最大的文件
})
```

每个路径独立测量，互不阻塞（并行）。

### 步骤 3：呈现（按用户的语言，不按路径）

每个测量结果翻译为：
- **是什么**：从规则库或路径推断（"QQ 聊天数据" / "npm 包缓存"）
- **多大**：人类可读（"4.5 GB"）
- **最近使用**：从 mtime 推断（"3 天前"）
- **能否处理**：可迁移 / 可删除 / 不要动

---

## 3. 与全盘扫描的关系

```
用户打开助手
     │
     ├─ 默认：定向扫描（秒级）→ 分类报告 → 用户决定下一步
     │                                │
     │                     ┌──────────┴──────────┐
     │                     ▼                     ▼
     │              点某个目录深度扫描        点「全盘扫描」
     │              （只扫那一个路径）        （现有的完整扫描）
     │
     └─ 也可以直接点「全盘扫描」
```

---

## 4. 实现要点

- **路径来源可插拔**：注册表/规则库/环境变量/上次扫描结果——新来源实现 `PathSource` 接口即可
- **每个路径独立测量**：一个路径失败不影响其他
- **去重**：多个来源可能返回同一路径
- **深度限制**：定向扫描只到 depth 2（用户点进去才加深）
